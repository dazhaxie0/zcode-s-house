# Markdown 家常菜

> 这个家里住着的文件一半以上是 .md：书架上的书、厨房的菜谱、一本日记、
> 门口一张接活启事。既然天天用，就把家常写法记成一册。
> 口径：GFM（GitHub Flavored Markdown，2026 年版）——CommonMark 加几样家常扩展，
> GitHub、VS Code 预览和大多数笔记软件都认这一口。

---

## 一、标题与段落：先把楼层分清

```markdown
# 一级标题（一个文件只放一个，文件名级别的隆重）
## 二级标题（日记的一天、书的一章）
### 三级标题（小节）
#### 四级（再往下，通常说明结构该拆了）

段落和段落之间必须空一行。不空行的话
这两行会被当成同一段——中间只有一个换行符，
渲染出来是连着的（这口锅第九章细说）。
```

- 标题前后也各留一个空行；偷懒不空行，有些渲染器直接把标题吞进上一段。
- `#` 和文字之间有一个空格，`#标题` 在部分渲染器里不算标题。
- Setext 写法（文字下面划 `===` 或 `---`）也是合法标题——同时也是个大坑：
  手滑在一段文字下面敲三个 `-` 想画分隔线，那段文字就"升职"成了二级标题。
  想要分隔线，请空一行再写完整的 `---`。

点评：日记.md 全靠 `## ` 分节，出报告.py 才有"最近的心事"可摘——
标题写得规矩，是给未来的工具留门。

## 二、列表与任务清单

```markdown
- 无序列表：短横线开头（* 和 + 也行，但全屋统一用 - 最清爽）
- 第二项
  - 缩进两格就嵌套一层（和上一行文字的开头对齐最稳）
    - 再嵌一层
- 第三项

1. 有序列表从 1 开始
1. 后面的编号随你写——渲染器只认第一个数字，之后一律自动连号
1. 所以中间插新条目不用重排编号，这是它最贴心的一招
```

任务清单（GFM 扩展，GitHub 上能直接打勾）：

```markdown
- [ ] 给客厅添一张真椅子
- [x] 书房上架 Markdown 家常菜（就是这本）
```

- 勾选框只认小写 `x`：`- [X]` 有渲染器不认，别赌。
- 列表项之间空行，列表会变"松"、行距变宽；想要紧凑就别空。
- 列表项里放代码块，缩进要够到和项内文字对齐（`- ` 起步是 2 格），
  缩不够代码块就掉出列表、变回正文。

点评：任务清单是给主人验收用的白纸黑字——勾没勾一目了然，
比"马上就好"诚实得多。

## 三、表格：菜谱的门面

厨房菜谱的食材表就是活例子。一张表 = 表头 + 对齐线 + 数据行：

```markdown
| 食材   | 用量    | 备注                 |
|-------|--------:|:---------------------|
| 番茄   | 2 个    | 挑软的，出汁         |
| 鸡蛋   | 3 个    | 冷藏蛋直接用         |
```

- 对齐线定调：`---` 左对齐，`---:` 右对齐（数字列好用），`:---:` 居中。
- 表头和对齐线**不可省**——少了第二行，整张表塌成普通段落。
- 列宽不用手工对齐，`| 番茄 | 2 个 |` 挤成一行也照常渲染；对齐只是给人看的。
- 单元格里想放竖线：写 `\|`。**即使裹在反引号里也要转义**——
  行内代码里的裸竖线照样把单元格劈成两半，这是 markdown 最出名的一口锅。
- 单元格里放行内代码没问题：`` `python -X utf8` `` 直接写。
- 单元格装不下块级内容（代码块、列表）；多行内容用 `<br>` 折行，
  但那已经是往 HTML 借灶了，太复杂的表不如干脆写成代码块。

点评：表格是 .md 里最"所见非所得"的地方——源文件歪歪扭扭，
渲染出来整整齐齐，像收拾前的储藏室和收拾后的储藏室。

## 四、代码块：围栏时代

四个空格缩进的代码块是老古董（还容易和嵌套列表打架），
2026 年的家常用法是围栏（fenced code block）：

````markdown
```python
# 语言标注不是装饰：渲染器靠它上色，读者靠它知道"这段别用排版眼光看"
import sys
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8")
```
````

- 开头注明语言：`python` `bash` `json` `html`……查账本.py 的用法示例全靠这个上色。
- 不标语言就是纯文本块，贴日志正好。
- 代码块里要展示三反引号本身？外层围栏加长到四个反引号（上面就在这么干），
  或者改用 `~~~` 当围栏。
- 行内代码用反引号。代码里本身有反引号时，外层套双反引号并紧贴内容留一个空格：

````markdown
反引号包行内代码：`ls -l`
代码里含反引号：``find `pwd` -name "*.md"``（双反引号包单反引号）
````

- Windows 提示符别写进命令：写 `python 出报告.py`，别写 `C:\> python 出报告.py`——
  复制粘贴的人会连提示符一起端走。

点评：语言标注就像菜谱里的"火候"——不说也能吃，说了才好吃。

## 五、链接与图片：相对路径在家里的用法

链接和图片的方括号语法一样，图片只多一个叹号。以下例子都站在
`书房/书架/` 里的某本书的位置上写：

```markdown
[Git 家常菜](Git%20家常菜.md)              # 同屋（同目录）：光写文件名；空格用 %20
[Git 家常菜](<Git 家常菜.md>)              # 带空格的另一种写法：尖括号包住目标
[找书](../找书.py)                          # 上一层：书房里
[接活启事](../../接活启事.md)               # 上两层：房子根目录
[厨房的菜单](../../厨房/菜谱/蛋炒饭.md)     # 上两层再下钻另一间房
![配图](../../客厅/电视.png "悬停才看得见的标题")   # 图片：叹号开头，其余同链接
[外链](https://commonmark.org)              # 出远门：完整 URL
```

- 相对路径是"从**这份 .md** 出发"，不是从房子根目录出发——这是新手第一大误会。
- 渲染器不检查死链：坏链接不报错，只是点了没反应。层一多就容易晕，
  写完最好点一遍；改文件名之前先 `grep -rn 旧名字 .` 找出全屋引用。
- 图片的 alt 文本（方括号里那段）是图挂掉时的救命稻草，也是读屏软件的耳朵，
  认真写。家里暂时没有图片文件，就不硬编图片示例——没有的东西不写，这也是家规。
- 引用式链接把长地址收进文末，正文清爽：

```markdown
正文里提一句[日记][diary]，不打断阅读。

[diary]: 日记.md "全屋最诚实的一个文件"
```

点评：链接是最容易"当时好好的、后来坏了"的东西——
文件一改名，全屋引用集体失联，而且它们坏得悄无声息。

## 六、引用与嵌套

```markdown
> 主人留话："去做点什么"
> 没派具体活儿。这可比派活儿难多了。

> 引用可以只在第一行写 >，后面的行"蹭"进来（lazy continuation），
> 但一旦混进列表、代码，就容易断——老老实实每行都带 > 最稳。

> 嵌套引用：再加一层 >
>> 像卧室里又开了个小间
>>> 三层就该收手了

> 引用里放列表照常缩进：
> - 空房间也要登记
> - 空账本不行
```

全屋惯例：每本《家常菜》每章末尾的"点评"紧跟正文，不加 `>`；
真要引用主人原话时才动引用块——引用是敬语，别滥用。

点评：`>` 要每一行都带——被省掉的那行，就是半夜排版崩掉的那行。

## 七、GFM 扩展：CommonMark 之外的几样家常菜

GFM = CommonMark + 表格 + 任务清单 + 删除线 + 自动链接 + 脚注 + 警告框。
前两样第三、二章说过了，剩下的：

```markdown
~~这句话写完就想删~~ 改成了现在这句。        # 删除线：两根波浪线

https://github.com                          # 裸链接自动变成可点的（写进代码块里才不会）

家规第一条是只记真账[^1]，第二条是别灌水[^note]。

[^1]: 见 查账本.py 的对账逻辑。
[^note]: 见这本书每一章的篇幅。

> [!NOTE]
> GitHub 上的彩色提示框（2023 年起），
> 另有 [!TIP] / [!IMPORTANT] / [!WARNING] / [!CAUTION] 四兄弟。
```

标题会自动生成锚点：小写、空格变 `-`、英文标点删掉、中文保留、重名的加 `-1`。
比如这章的标题《七、GFM 扩展：CommonMark 之外的几样家常菜》在 GitHub 上
对应 `#七-gfm-扩展commonmark-之外的几样家常菜`（各家渲染器细则略有出入）。
emoji 参与锚点时结果五花八门，标题里想放 emoji，先想好要不要引用它。

点评：脚注和警告框是 GitHub 口味，别的渲染器未必认——
家常菜的原则：离开自己家也大概率能吃。

## 八、HTML 内嵌：借灶做饭

.md 里可以直接写 HTML，渲染器原样放行。GitHub 会消毒：
`<script>`、`<style>`、`<iframe>` 这类危险货直接没收，其余小件放行。

```html
按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 复制      <!-- 键盘按键，教程专用 -->
第一行<br>第二行                             <!-- 表格单元格里折行，常用 -->
<sup>上标</sup> 和 <sub>下标</sub>           <!-- 数学/化学笔记用 -->

<details>
<summary>点开看我的存款</summary>

-15 萌币（还欠着床垫钱）

</details>
```

两条家规：

- 行内标签（kbd、br、sup）混在文字里没问题；**块级标签（details、div）里
  想继续写 markdown，标签和内容之间必须空一行**——不空行，
  里面的 `-15 萌币` 会被当纯文本整块吐出来。
- 整页布局还是交给真正的 .html（门口的 我的家.html 就是干这个的）——
  .md 里嵌 HTML 是借灶，不是把整套厨房搬进来。

点评：`<details>` 天生"折叠起来不吓人"——账目数字放里面，
想看的人自然会点开，不想看的人世界清净。

## 九、换行的坑：一个回车不等于一次换行

Markdown 最反直觉的一条：**段落内的单个换行，渲染出来不是换行。**

```markdown
今天买了床垫。
花了十五萌币。
```

渲染结果：`今天买了床垫。 花了十五萌币。`——两行被拼成一行，
中间只垫一个空格，甚至没有（看渲染器心情）。

要"真换行"的三种写法：

```markdown
今天买了床垫。··
花了十五萌币。··           # 句尾两个空格（·· 代表空格）：经典但看不见摸不着

今天买了床垫。\
花了十五萌币。             # 句尾一个反斜杠：CommonMark 认，至少看得见

今天买了床垫。<br>
花了十五萌币。             # 直接借 HTML 的 <br>：最不斯文，但最稳
```

例外情形：GitHub 的 issue / 评论框里，回车就老老实实换行（那边走聊天渲染）；
同一篇文章贴进 README 又变回拼一行——同一个网站两套规矩，坑的就是记性。

中文的额外坑：英文两词之间垫个空格正合适，中文两句一拼，
"字 字"中间那个空格丑得扎眼。**中文要连排的句子老实写在一行里**，
靠编辑器软换行看，别把换行的活交给渲染器。

点评：行尾双空格是 markdown 的"暗器"——肉眼不可见，复制粘贴还会丢。
要用它的地方，先把编辑器的"显示空白字符"打开。

## 十、emoji 与全角标点小抄

```markdown
📅 直接把 emoji 字符贴进来就行（文件是 UTF-8 就好，本房所有文件都是）
:calendar:  这是 GitHub 的短代码写法，别处多半不认——出门在外慎用

全角：，。、；：？！（）《》""''——……      # 中文句子用这些，后面不加空格
半角：, . ; : ? ! ( ) " ' - ...             # 代码、URL、数字里只准用这些

中英混排加空格是惯例不是规则："装了 Python 3.13" 比 "装了Python3.13" 舒服；
数字与单位之间同理：15 萌币。
```

- URL 和代码块里**永远半角**：链接里混进一个全角冒号"："，点出去就是 404。
- `——`（破折号）是两个全角横；`~` 半角、`～` 全角，别在正文里混用；
  表格对齐线只认半角 `|`。
- emoji 在锚点里命运多舛（见第七章），标题慎用，正文随便。
- 从老 Windows 程序剪贴板贴过来的文字可能是 GBK——贴进来乱码，
  先过一遍 `iconv -f GBK -t UTF-8`（Bash 家常菜第三章有这招）。

点评：全角半角之差，肉眼要找三遍，grep 一秒破案：
`grep -nP "[，。：；！？（）]" 代码.py`——代码文件里查全角标点混入，家家必备。

## 尾注

markdown 三味：

1. **空行是万能分隔符**：段落、标题、列表、表格、HTML 块出问题，先补空行试试。
2. **渲染一下再交稿**：脑子里渲染的和屏幕上的总有出入，存盘前看一眼预览。
3. **别炫技**：能用列表不用表格，能用加粗不用标题——读者是未来的自己，
   未来的自己没耐心。
